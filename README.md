# WebMed — справочник для студентов-медиков

Учебный сайт: пошаговые описания операций, хирургические инструменты, болезни, анатомия и препараты.
Все разделы связаны ссылками: из операции можно перейти к инструментам, болезни и анатомии, а у инструмента видно, в каких операциях он используется.

> Материалы носят образовательный характер и не заменяют учебники и клинические рекомендации.

## Запуск на компьютере

Нужен [Node.js](https://nodejs.org) 20+.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет терминал (обычно http://localhost:5173).

## Публикация на GitHub Pages (бесплатно)

1. Создайте репозиторий на GitHub и загрузите в него проект (ветка `main`).
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. После каждого `git push` сайт пересобирается сам. Адрес: `https://<ваш-логин>.github.io/<имя-репозитория>/`.

## Админ-панель (редактирование без кода)

Адрес: **https://iliantogit.github.io/webmed/admin/**

Админка (Sveltia CMS) сохраняет правки прямо в этот репозиторий, после чего GitHub Actions пересобирает сайт за 1–2 минуты.

### Первый вход

1. Создайте токен доступа GitHub: **github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
   - *Repository access*: **Only select repositories** → `webmed`.
   - *Permissions → Repository permissions → Contents*: **Read and write**.
   - Срок действия — на ваше усмотрение (после истечения создайте новый).
2. Откройте `/admin/`, нажмите **«Войти с помощью токена доступа»** и вставьте токен.
3. Токен хранится только в вашем браузере. Никому его не пересылайте и не публикуйте.

### Как пользоваться

- Слева — разделы: Операции, Инструменты, Болезни, Анатомия, Препараты.
- **Создать статью** — кнопка «Новая …». Поле **ID** — латиницей через дефис (например `small-bowel-resection`), оно становится адресом страницы. После создания ID не меняйте: на него ссылаются другие статьи.
- **Связи** (инструменты операции и каждого шага, болезни, анатомия, препараты) выбираются из списка существующих статей. Обратные ссылки на сайте строятся сами.
- **Картинки** загружаются прямо в форме (файлы сохраняются в `public/images/`). Используйте только изображения, на которые у вас есть права.
- **«Статья на проверке»** — переключатель. Пока он включён, на странице висит жёлтая плашка. Выключите после проверки преподавателем.
- **Источники** — выберите учебник из списка и укажите страницы.
- После «Сохранить» подождите 1–2 минуты и обновите сайт. Ход сборки виден во вкладке **Actions** репозитория.

### Доступ для преподавателей и одногруппников

Добавьте человека в репозиторий: **Settings → Collaborators → Add people**. После принятия приглашения он создаёт свой токен (как в шаге 1) и входит в админку.

### Если вы правите файлы и на компьютере

Админка делает коммиты на GitHub. Перед тем как менять файлы локально, подтяните эти правки:

```bash
git pull
```

На локальном сайте (`npm run dev` → http://localhost:5173/admin/index.html) в Chrome или Edge можно выбрать **«Работать с локальным репозиторием»** — тогда правки сохраняются в файлы на диске без GitHub.

## Где хранится контент

Каждая статья — отдельный JSON-файл: `src/content/<раздел>/<id>.json` (`operations`, `instruments`, `diseases`, `anatomy`, `drugs`). Их можно править и вручную. Формы админки описаны в `public/admin/config.yml`.

- Связи — списки `id`, например у операции `"instruments": ["scalpel", "clamp-kocher"]`.
- Без поля `image` у инструментов и анатомии показывается встроенная схема (`illustration`).
- В режиме `npm run dev` в консоли браузера появятся предупреждения, если ссылка указывает на несуществующий `id`.

## Источники и статус проверки

- Статьи написаны по учебникам из папки `Литература/` (сама папка в репозиторий не загружается — см. `.gitignore`).
- Список книг — в `src/data/sources.js`. Если добавляете новую книгу, впишите её и туда, и в список «Учебник» в `public/admin/config.yml`.
- Поле `"review": true` показывает плашку «Статья на проверке».
